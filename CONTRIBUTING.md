# Contributing to punchcutter

Thank you for looking. The rules below are the ones the engine's design
depends on, and each says why.

## Where a change goes

**The GPU-first rule.** The CPU keeps I/O: reading a font file, finding fonts
through fontconfig, writing a cache. Anything that is computation over data
the GPU can hold belongs in a Slang module under `slang/`: shaping, coverage,
table walks, decisions about a glyph. Nothing on the CPU side reads a lookup,
a coverage table or a subtable format, and there is no CPU shaper, not even a
reference one, because a second implementation is a second set of answers. If
you think something cannot be done in the shader, say why in the pull
request.

**The engine knows nothing about its consumer.** No module or crate assumes
what is drawing the text, which descriptor sets a host uses beyond the curve
buffers' set 1, or when it shapes.

## Languages and layouts

- **Slang, not WGSL**, for every shader. Shaders are compiled to SPIR-V by
  slangc and loaded through wgpu's passthrough.
- **Shared layouts are declared once, in Rust.** The arena and the shaping
  dispatch are declared in `shape/src/abi.rs` through `punchcutter_core::decl`;
  `slang/shape_abi.slang` is generated by `cargo run -p punchcutter-shape
  --bin gen-slang` and checked in. Never edit it by hand: a test fails when
  the file on disk differs from the rendering, and another compares every
  struct's offsets with slangc's reflection. The curve buffers in
  `text/src/layout.rs` are mirrored by hand in `slang/text.slang` and pinned
  by the same kind of reflection test.
- Every field of a shared struct is a `uint`, an `int`, a `float` or an array
  of them. No 3-vectors: std430 aligns them to 16 bytes (docs/arena.md,
  *Layout rules*).
- **Untrusted bytes are bounded.** A font is somebody else's file. Every read
  from the arena is clamped to what was bound, and every list a table states
  is capped and charged against the operation budget before its first
  iteration. Do not make a budget charge a loop's exit condition: one driver
  miscompiled exactly that (`faceFor` in `slang/shape.slang` says how).

## Licensing

The engine is MIT. Code brought in from elsewhere comes under a licence
compatible with that, keeps its own notice where it lands (see
`slang/text.slang`'s header for how), and is listed in `NOTICE`.

## Dependencies

`Cargo.lock` is committed and is the source of truth: build and test with
`--locked`. Never run a bare `cargo update` or `cargo add`. Every change to the
lockfile goes through a release-age cooldown (`cooldown.toml`: a registry
version younger than seven days is refused; versions already in the lockfile
are exempt), with `cargo cooldown update` or `cargo cooldown add <crate>`.
`cargo cooldown add` cannot carry feature flags: add the crate plain,
hand-edit the features, then run `cargo cooldown check`. If your change adds
or updates a crate and you do not have the tool, open the pull request as it
is and the maintainer re-resolves the lockfile.

## Formatting

Rust is formatted with rustfmt's defaults; `cargo fmt --all` before a commit,
and CI checks it. A table laid out by hand (grouped corpus strings, say) keeps
its layout with `#[rustfmt::skip]` on that item, never by leaving a file
unformatted.

## Tests

- **Unit tests live beside their file** as a sibling module: `foo.rs`
  declares `#[cfg(test)] mod tests;` and the tests are in `foo/tests.rs`.
- **Before a pull request**: `cargo check --locked --workspace --all-targets`
  with **zero warnings** (CI sets `RUSTFLAGS=-D warnings`), and `cargo test
  --locked --workspace` green. Both need slangc on `PATH`.
- **If you touched a shader**, run the conformance runner (`cargo run -p
  punchcutter-shape --example conform`) for shaping and the render example
  (`cargo run -p punchcutter-text --example render`) for coverage, and paste
  their summary lines into the pull request. If you changed a bound in
  `ot.slang` or `shape.slang`, also run `cargo run -p punchcutter-shape
  --example garbage -- --hostile` under lavapipe.
- **A test fixture must identify nobody.** `tools/scrub-check.sh` scans the
  tracked tree for the shapes of private data (addresses, email addresses,
  private keys, home paths) and exits non-zero on a hit. Pointing
  `$PUNCHCUTTER_SCRUB_WORDS` at a file of your own words, one per line and never
  committed, makes it look for those too. A hit on a word is read and judged
  (a coincidental substring is fine), never suppressed.

## Logging

The library crates never print. What a load, a cover or a closure did goes to
`tracing`, once per event and never per frame or per glyph; a consumer that
installs a subscriber sees it. The examples print, because they are harnesses.

## The public voice

Every comment and document is written for a reader who has never met the
authors and does not know the project's past:

- Explain the code as it is. No history ("used to", "previously", "moved
  from"), no personal or machine names, no dates as narrative, and no labels
  from anyone's private notes.
- A comment that cites a document names its section: `docs/arena.md, *The
  merged glyph space*`. Never a section number, and never a document that is
  not in this tree. `docs/check-links.sh` checks every `docs/…md` pointer.

## Commits and pull requests

Stage files by name (`git add <file> <dir>/`), never with `git add -A` or
`git add .`, so that nothing reaches a commit by a wildcard. Small, focused
commits whose messages say what changed and why. In the pull request: what
the change is, what you ran, and anything you found that you did not fix.
